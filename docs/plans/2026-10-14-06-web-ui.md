# Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build remora's admin console (Login, Overview, Providers with OAuth accounts, Aliases, Keys, Logs, Settings) on HeroUI v3, then embed it in the remora binary and serve it at `/`.

**Architecture:** `web/` is a Vite SPA. File-based TanStack Router routes act as containers: they read URL search params, call the TanStack Query hooks generated by `@hey-api/openapi-ts` from `api/openapi.yaml`, and pass props to presentational compound components. `vite build` writes to `internal/web/dist`. A small Go package embeds that directory with `go:embed`. It serves hashed assets as immutable, serves `index.html` as `no-cache`, and sends unknown page paths to `index.html` (SPA fallback). A few logic files are copied once from Bifrost's UI and carry a header that credits the source.

**Tech Stack:** Bun 1.4, Vite 8, React 19, TypeScript 7 (strict), HeroUI v3 (`@heroui/react` + `@heroui/styles` 3.2.x) on Tailwind CSS v4 (`@tailwindcss/vite`), `react-aria-components` (the HeroUI peer, used for `useDragAndDrop` and `FileTrigger`), `@gravity-ui/icons` (HeroUI's icon set), TanStack Router 1.170 (`@tanstack/router-plugin/vite`), TanStack Query 5, `@hey-api/openapi-ts` 0.99 (`@hey-api/client-fetch` + `@tanstack/react-query` plugins), recharts 3, oxlint + oxfmt, Vitest 5 + Testing Library + jsdom, Playwright 1.64. Go 1.27 `embed` + `net/http`.

**Spec:** `docs/specs/2026-10-14-remora-0.1-design.md` (sections "The UI", "Management API", "Authentication", "Packaging"). Research: `docs/research/2026-10-14-bifrost-ui-reuse.md`.

Versions were checked on 2026-10-14 with `npm view`. `@heroui/react` 3.2.6 declares `react-aria-components ^1.21.1` as a peer, re-exports `useTheme`, `useListData`, `cn` and `Virtualizer`, and its `ListBox` passes every `react-aria-components` `ListBox` prop through (`dist/components/list-box/list-box.d.ts`), so `dragAndDropHooks` works. `@hey-api/openapi-ts` 0.99.0 bundles the fetch client (`dist/clients/fetch`) and needs Node 22.18 or later, or Bun, which stands in for `node` when Node is absent. The HeroUI quick start says to put `@import "tailwindcss";` and then `@import "@heroui/styles";` in the CSS entry, with no provider. Dark mode works by setting the `dark` class or `data-theme="dark"` on `<html>`, which HeroUI's `useTheme` does.

**Linter choice: oxlint + oxfmt, not Biome.** The owner's rule is Rust tooling first. Bifrost's UI already uses oxlint and oxfmt, so the copied files arrive formatted for them. Biome would add a second set of rules with no gain.

## Global Constraints

- "**No custom CSS and no custom theme**: HeroUI's own components, tokens, light and dark modes." The only CSS file is `web/src/index.css`, and it contains exactly `@import "tailwindcss";` and `@import "@heroui/styles";`. No inline `style` props. Chart colours are HeroUI CSS variables (`var(--accent)`, `var(--success)`, `var(--danger)`, `var(--warning)`, `var(--muted)`, `var(--border)`).
- "English, left to right." User content (prompts, responses) is shown with `dir="auto"` so Persian text renders correctly. It is never rewritten.
- "Built into the binary; no Node at runtime."
- "Every list is paged, filterable and searchable." No virtualization: never import `Virtualizer`.
- "Each copied file starts with `// Derived from maximhq/bifrost ui/<path> (Apache-2.0); modified.` and `THIRD_PARTY_NOTICES.md` credits it. No brand strings or images are copied." Nothing is copied from `app/enterprise` or `app/_fallbacks`. Code is copied once and never synced.
- Anti-goal "Leaking the engines": the words Bifrost, CLIProxyAPI and Maxim never appear in UI copy. They appear only in the Settings → About credits and in the copied-file headers.
- No owner host names, domains, product names, keys or deployment details anywhere in `web/`.
- Owner component rules:
  - Compound components in Radix style, built with `Object.assign(Root, { Part })`.
  - Data fetching happens only in route files and in hooks under `-hooks/`. Components receive props.
  - No `use*.ts(x)` file inside any `components/` or `-components/` folder.
  - A component with one consumer lives next to its route, in `routes/**/-components/`. The `-` prefix makes TanStack Router ignore the folder.
  - A component with two or more consumers lives in `src/components/`.
- The generated API client (`web/src/client/`) and the router tree (`web/src/routeTree.gen.ts`) are committed. CI fails when regenerating them changes either one.
- Conventional Commits with scope `web` (`feat(web):`), `build(docker):`, `ci:`, `test(e2e):`. All work happens on branch `plan/06-web-ui` and lands as one pull request into `main`.

## Plan 05's contract as the UI uses it

The UI imports generated names from plan 05's `operationId`s (`api/openapi.yaml`), so this table is the interface.
It repeats plan 05's operation ids and paths exactly; plan 05 owns them, and a change there changes this table and the
imports in each route.

Conventions for every list (plan 05, Task 1):
- Query: `limit` (1–200, default 50), `offset`, `q` (free-text search). The UI keeps `page` (1-based) and `pageSize`
  (25, 50 or 100) in its URL and sends `limit = pageSize`, `offset = (page − 1) × pageSize`.
- Response: `{ items: T[], total: number }`.
- Errors: `{ error: { message: string, type: string, code: string } }`.
- Auth: the session cookie is HTTP-only and `SameSite=Strict`, so same-origin `fetch` and WebSocket requests send it
  with no extra code.

The UI's own view types in later tasks (`LogSummary`, the `summarize` input, the `keyId` URL parameter, the login
phases' `authUrl` and `verificationUrl`, a provider's display group and key hints) are built from these schemas in
the route containers, by one small mapping function per page. The generated request and response types are always
plan 05's. Display groups are derived, never sent (README "One provider model"): API key = `builtin` +
`openai-compatible`, Decisions = `typesafe-compatible`, Speech-to-text = `soniox`, Subscription = the `accounts`
resource grouped by `Account.provider`. Key hints are the provider's key names.

## Review Focus

1. **Open redirect through `/login?redirect=`.** A link such as `/login?redirect=//evil.example` must land the user on `/`, not on another site. Covered by `safeRedirect` tests (Task 3).
2. **A secret shown once must not survive.** Key values and API-token values must never be stored in the query cache, the URL, `localStorage` or the DOM after the dialog closes. Reloading the page must not bring a value back. Covered by `SecretOnce` tests (Task 4), the key-create container rule (Task 10) and the Playwright smoke test (Task 13).
3. **The UI's glob preview can disagree with the server.** The allowlist preview must use the server's `proxy.Allowed` rules: `*` matches any name, a trailing `/*` matches any depth below it (`antigravity/*` matches `antigravity/a/b`), and anything else follows Go `path.Match` (`openai/gpt-*` does not match `openai/gpt-5/x`). If it is wrong, the UI tells the user that a key can reach models it cannot reach, or the reverse. Covered by `globMatch` table tests (Task 10).
4. **Persian text with ZWNJ in logs.** Request and response bodies with U+200C and right-to-left text must display byte for byte. Pretty-printing JSON must not change the text, and a non-JSON body (an SSE stream) must be shown raw. Covered by `formatBody` tests (Task 11).
5. **The SPA fallback hides API typos and stale HTML.** `GET /api/typo` must return 404, not `index.html` with status 200. A missing `/assets/x.js` must return 404. `index.html` must be `no-cache`, so that after an upgrade a browser never loads old HTML that points to deleted hashed assets. Covered by Go handler tests (Task 2).

Also covered, with lower risk:
- A pasted redirect URL from a different login attempt. `parseRedirectUrl` rejects a mismatched `state` (Task 8).
- Polling continuing after the login dialog closes. The query is disabled when the dialog closes, and polling has a deadline (Task 8).

- [ ] **Step 3: Implement `New(fsys fs.FS) http.Handler` and `Handler() http.Handler` in `internal/web/web.go`**

Read `index.html` once inside `New`; if it is missing, every request returns 503. Rules, in this order:
1. A method other than GET or HEAD returns 405 with `Allow: GET, HEAD`.
2. A path with the prefix `/api/` or `/v1/` returns 404.
3. A path under `/assets/` that exists is served with `http.ServeFileFS` and `Cache-Control: public, max-age=31536000, immutable`.
4. Any other existing file except `index.html` is served with `public, max-age=3600`.
5. A path whose last segment contains a `.` returns 404.
6. Everything else, including `/` and `/index.html`, is served as the index bytes through `http.ServeContent`, with `Cache-Control: no-cache`.

Set `X-Content-Type-Options: nosniff` on every response. `Handler()` uses `fs.Sub(dist, "dist")`. Do not use `http.FileServerFS` for the index, because it redirects `/index.html` to `/`.

## Corrections found during implementation

- **Toolchain (Task 1).** `bun init` made a subfolder, so `package.json` is written by hand. The OpenAPI generator
  needs the TypeScript 6 compiler API, so `typescript` is pinned to 6.0.3 for it and type checking runs TypeScript
  7.0.2, installed as the alias `typescript-7`. `GET /api/logs/live` is excluded from code generation (that filter
  also needs `orphans: true`). `@types/node` and vitest `globals` are added for the plan's tests.
- **Client and components (Tasks 3–4).** Tests set an absolute `baseUrl` because Node's `Request` rejects relative
  URLs. HeroUI's spinner has role `status`, so tests assert that; `StatusChip` sets `data-color` itself. HeroUI's
  router provider wraps the outlet so its links navigate through the router. Login refuses redirects back to
  `/login` and control characters.
- **Embedding (Task 2).** The web stage runs on the build platform; `.dockerignore` excludes
  `internal/web/dist/`. The handler also 404s exact `/api` and `/v1`, never serves directories, and gives the index
  a strong ETag so `no-cache` revalidates with 304.
- **Copied UI (Task 5).** Copied from the pinned engine tree (`9237ec0`; the plan's `72457fe` is not in the
  checkout). Icons that load images and inline styles were removed.
- **Overview (Task 6).** The stats series carries only requests and errors, so tokens, cost and latency are bar
  charts per provider; volume is the time series.
- **Providers (Tasks 7–8).** The contract has no provider `enabled` field or status filter, so there is no enable
  switch and grouping and status filters run on the client over one 200-row page. All subscription providers show,
  with account counts. `ProviderDraft` carries `allow_private_network`; a blank key value keeps the stored key.
- **Aliases and keys (Tasks 9–10).** Glob matching follows the server's `path.Match` (no `!` negation). API-key
  provider models are typed, since providers list no models. The list runs one chain call per visible alias; the
  cooling and enabled filters run on the client. Keys show "Created" (no last-used time in the contract). A new
  key's or token's value is stripped from the query and mutation caches and shown once.
- **Logs (Task 11).** The detail drawer shows what `LogEntry` carries (no HTTP status, endpoint or first-byte time).
  Bodies are re-indented token by token so numbers and escapes stay as sent. Live mode closes its socket when it
  turns off.
- **Settings (Task 12).** Import sends `{document, prune: true}` with no secrets; unresolved `env:` references come
  back as plan errors.
- **Smoke tests (Task 13).** The key dialog's labels are "Create key" and "Secret". Without a session an unknown
  `/api` path answers 401, so the Go test checks 401 first and 404 after signing in. CI reads remora's published port
  with `docker compose port`, since compose publishes an ephemeral port. Locally, Playwright may need
  `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to use an installed Chromium.
- **Review fixes.** Import shows each client key value apply generated, one at a time, and keeps them out of the
  caches; a partly failed apply shows the committed keys' values and refetches. Live logs restart from the new first
  page when a filter changes.
