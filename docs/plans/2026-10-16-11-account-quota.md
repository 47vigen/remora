# Account Quota Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show, for every Antigravity, Codex and Claude subscription account, how much of each quota window is left
and when it resets, on one console page, read with the account's own credential at a bounded upstream cost.

**Architecture:** A new package `internal/quota` sends each provider's private usage request upstream through the
OAuth engine's `POST /v8/management/requests/api-call` (one new client method), parses the answer in Go, and keeps
one overwritten snapshot per account in a new store table. One sequential worker polls due accounts, at least 2 s
between upstream calls; Codex and Claude accounts with a fresh passive snapshot (the engine's `quota.signals`) are
not polled. `GET /api/quota` merges snapshots with status and cooldowns; `POST /api/quota/refresh` queues checks. A
**Quota** console page renders it.

**Tech Stack:** Go 1.27, `net/http`, `encoding/json`, `go.yaml.in/yaml/v3`, `testing/synctest`, SQLite, oapi-codegen,
Bun + Vite + HeroUI v3 + TanStack Query (`web/`), Docker Compose e2e with the fakes image.

**Spec:** `docs/specs/2026-10-16-quota-routing-mcp-design.md`, "1. Account quota" plus Goals, Non-goals, Anti-goals
and Delivery. Evidence: `docs/research/2026-10-16-quota.md`.

Engine facts were read from the engine at `CLIPROXYAPI_VERSION=v8.0.31` (`engines/versions.env`). `C/` =
`engines/cliproxyapi`, `AT` = `C/internal/api/handlers/management/api_tools.go`.

## Global Constraints

- **Never spend quota to measure quota.** No request that runs inference; the only upstream calls are Task 4's.
- **No load on upstreams.** One worker, strictly sequential, at least `2s` between upstream calls (every api-call
  counts, `loadCodeAssist` and the second Antigravity base included). At start only accounts whose last check is
  older than the interval are due, through the same spaced queue.
- `REMORA_QUOTA_INTERVAL`: default `15m`, refused below `5m`, `0` = no background polling, on-demand refresh stays.
  On-demand: `60s` floor per account. 429 or 5xx: next poll after `min(interval·2^n, 4h)` for the n-th consecutive
  failure.
- **A number never lies.** Unknown is `null` in store, API and UI ("Unknown"), never 0 % or 100 %. Parsers accept
  missing fields.
- Each call sends the engine's own User-Agent for that provider, pinned by an `engine`-tagged test (Task 4).
- No engine change. Engine names never reach a user-facing string; snapshot errors are Task 3's `Msg*` constants.
- No owner infrastructure, host names or keys anywhere; fixtures use `example.test` and fake tokens. e2e talks to the
  fakes only.
- `GET /api/accounts` keeps its `Account.quota` shape.
- Migration `internal/store/migrations/0009_account_quota.sql`. `user_version` counts files in sorted order
  (`internal/store/store.go:89-108`): plan 12 owns `0007` and `0008`; if either plan lands with a different count, renumber so files stay in order.
- Tests before code. After every task: `go test -race ./...`, `golangci-lint run`; web tasks also `bun run typecheck`,
  `bun run lint`, `bun run test` in `web/`. Final: `make image fakes-image e2e`.
- Conventional Commits with scopes. `CHANGELOG.md` is generated by release-please from the squash commit: no hand
  edit; the PR title is its line, `feat(quota): account quota page, poller and API`.
- Branch `account-quota`, one PR to `main`.

## Review Focus

1. **A provider drops a field or changes its envelope.** The unreadable window is `remaining: null`, the others still
   show, nothing reads 0 %. Test: Task 3, `TestParsersReportMissingAsUnknown`.
2. **A check fails after a good one.** Windows, plan and `fetched_at` stay; only `error` and `checked_at` change.
   Test: Task 5, `TestWorkerKeepsLastGoodOnError`.
3. **An account is deleted while queued or mid-check.** Dropped without an error loop; the row cascades. Test: Task 5,
   `TestWorkerDropsDeletedAccount`.
4. **The engine is restarting** (`Credentials` fails). The worker waits the spacing and retries; it never spins.
   Test: Task 5, `TestWorkerEngineDownDoesNotSpin`.
5. **A passive Codex snapshot observed an hour ago.** `reset-after-seconds` counts from `observed_at`. Test: Task 3,
   `TestPassiveCodexResetFromObservedAt`.

`nextPoll`, in order: not polled when interval is 0, the row or credential is disabled, the credential is missing,
the provider is not `Supported`, or `q.Error == MsgSignIn` and the credential's `UpdatedAt` is not after
`q.CheckedAt`. `q == nil` → zero time (due). Else `at = q.CheckedAt + min(interval·2^failures, MaxBackoff)`; codex
or claude with `c.Quota.ObservedAt` → `at = max(at, ObservedAt + interval)`; exhausted (`LimitReached`, or every
window known and 0) with the earliest zero-window reset after `q.CheckedAt` → `at` = that reset.

Loop: each round reads `store.Accounts` and `eng.Credentials` once, takes the on-demand queue's head, else the
account with the earliest `nextPoll ≤ now`, checks it, writes the snapshot with `CheckedAt = now`, then sleeps until
the next due time capped at 1 minute (new accounts), or until `Refresh` wakes it. On `upstreamError` 401/403 it calls
`RefreshCredential(c.Name)` and fetches once more only if that succeeded. `Spacing` wraps `Engine.APICall`, so the
calls inside one check are spaced too. A `PutAccountQuota` failure for a deleted account drops it from queue and
failure map.

| outcome | snapshot (other fields kept) | failures |
|---|---|---|
| success | Plan (kept when ""), Windows, LimitReached, Source `poll`, `FetchedAt = now`, Error "" | 0 |
| 401/403 after the refresh path; engine 400 on api-call; no project | Error `MsgSignIn` | same |
| 429 | `MsgRateLimited` | +1 |
| 5xx; engine 502 | `MsgUnavailable` | +1 |
| other 4xx | `MsgRefused` | same |
| parse error | `MsgUnreadable` | same |
| other engine error | `MsgFailed` | same |
