# Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public repository that builds one image from source, holding remora, Bifrost and CLIProxyAPI. remora
supervises both engines on loopback and answers `/healthz` and `GET /api/system/version` on its one port. An e2e
harness with fakes proves this against the built image in CI.

**Architecture:** `remora serve` loads config from env, opens the SQLite store, generates the admin password and
engine credentials at first boot, renders each engine's config file, and starts the engines as child processes.
They are bound to `127.0.0.1` and checked against `versions.json`. remora opens its public listener only when both
engines are healthy. The image is a multi-stage build: remora is pure Go, cross-compiled; each engine is built with
cgo from its git submodule; the runtime base is glibc with `tini` as PID 1.

**Tech Stack:** Go 1.27, `log/slog`, `net/http` ServeMux patterns,
`modernc.org/sqlite`, `golang.org/x/crypto/bcrypt`, `go.yaml.in/yaml/v3`, Docker Buildx, Docker Compose,
GitHub Actions, golangci-lint v2.

**Spec:** [`docs/specs/2026-10-14-remora-0.1-design.md`](../specs/2026-10-14-remora-0.1-design.md). Shared contracts:
[`docs/plans/README.md`](README.md). Work on branch `plan-01-foundation`. Open one pull request into `main`.

## Global Constraints

- Go module `github.com/47vigen/remora`, `go 1.27`. Packages and names come from the shared contracts.
- Engines are git submodules under `engines/`. They are built in their own module context and never imported.
  remora never edits a file inside `engines/`.
- One exposed listener: `REMORA_LISTEN`, default `:8080`. The engines bind `127.0.0.1` only. The ports are front door
  `18080`, OAuth engine `18317` and Soniox adapter `18090`, overridable through `REMORA_PORT_ROUTER`,
  `REMORA_PORT_ACCOUNTS` and `REMORA_PORT_SPEECH`. No engine name appears in an operator-facing variable.
- Data layout: `$REMORA_DATA/remora.db`, `$REMORA_DATA/bifrost/`, `$REMORA_DATA/cliproxyapi/`. Default `/data`.
- `REMORA_ENGINE_DIR` defaults to `/usr/local/lib/remora/engines` and holds the engine binaries and `versions.json`.
- `REMORA_ADMIN_PASSWORD` applies only while the store has no admin: at first boot it becomes the password, and when
  it is absent remora generates one and prints it once to the log. Afterwards the stored password wins and the
  variable is ignored. remora stores only a hash.
- `REMORA_MASTER_KEY` (base64, 32 bytes) encrypts secrets at rest; when unset, plan 02 reads or generates
  `$REMORA_DATA/master.key`.
- `REMORA_LOG_LEVEL` is one of `debug`, `info`, `warn` or `error`. Default `info`.
- Runtime base is glibc: CLIProxyAPI's plugin host needs it. Never alpine or musl.
- Images are multi-arch ready (amd64, arm64).
- The repo is public from the first commit. No owner host names, domains, product names, keys or deployment details
  anywhere, including fixtures.
- Small focused files, `context.Context` first, errors wrapped with `%w`, table-driven tests, `log/slog`, no global
  state. The ldflags-set `version.Version` is the one exception.
- Conventional Commits with scopes. e2e tests carry the build tag `e2e`.

## Review Focus

1. **Second boot on the same `/data`.** Restarting the container must reuse every credential. It must not print a new
   admin password. Bifrost must accept the re-rendered `config.json`, because its first admin already exists.
   Covered by `TestEnsureCredentialsIsStable` (Task 8) and the e2e `TestRestartKeepsState` (Task 12).
2. **A `/data` that the non-root user cannot write**, such as a bind mount owned by root. `serve` must fail at once
   with an error that names the path. Starting the engines and letting them crash-loop is the wrong outcome. Covered
   by `TestPrepareDataDirRejectsReadOnly` (Task 9).
3. **An engine that keeps crashing.** `/healthz` must answer 503 and name the engine. The restart backoff must cap at
   30 s and keep trying. Covered by `TestHealthzDegraded` (Task 9), `TestNextBackoff` and
   `TestRestartsCrashedEngine` (Task 7).
4. **SIGTERM while the engines are still starting.** `Start` must return and no child process may survive. Covered
   by `TestStartCanceledKillsChildren` (Task 7).
5. **A store written by a newer remora (a downgrade).** `Open` must refuse with `ErrSchemaTooNew` and never migrate
   down. Covered by `TestOpenRejectsNewerSchema` (Task 4).

### Task 4: `internal/store`

**Driver: `modernc.org/sqlite`.**
- It is pure Go, so remora builds with `CGO_ENABLED=0`, cross-compiles to arm64 without a C toolchain, and runs
  `-race` tests anywhere.
- It is maintained, plugs into `database/sql`, and sets pragmas through the DSN.
- The engines need cgo, but remora's own binary stays free of it.

**Migrations:** `.sql` files are embedded with `//go:embed migrations/*.sql`, named `NNNN_<name>.sql` and applied in
order. Each file runs in its own transaction. The applied count is `PRAGMA user_version`, so no extra library and no
migrations table are needed. Numbers form one global sequence, one per plan: plan 01 `0001`, plan 02 `0002`, plan 03
`0003`, plan 04 `0004` (reserved; plan 04 adds no table), plan 05 `0005`. Files sort by name and the runner counts
files, so an unused number leaves no gap in `user_version`. A plan that needs a second file takes the next free
number after the last plan's and says so.

**Files:**
- Create: `internal/store/store.go`, `internal/store/settings.go`, `internal/store/engine_state.go`,
  `internal/store/migrations/0001_init.sql`
- Test: `internal/store/store_test.go`

```go
type Engine struct {
	Name      string   // "bifrost" | "cliproxyapi"
	Bin       string
	Args, Env []string // Env is the child's complete environment (exec.Cmd.Env semantics)
	HealthURL string
}

type EngineVersion struct {
	Version string `json:"version"` // the release tag, e.g. "transports/v2.3.0"
	SHA256  string `json:"sha256"`  // hex of the binary built into the image
}

var (
	ErrEngineMissing   = errors.New("supervise: engine binary missing")
	ErrVersionMismatch = errors.New("supervise: engine binary does not match versions.json")
	ErrUnhealthy       = errors.New("supervise: engine did not become healthy")
)

func LoadVersions(path string) (map[string]EngineVersion, error)
func VerifyBinary(bin string, want EngineVersion) error // ErrEngineMissing | ErrVersionMismatch

type Options struct {
	HealthTimeout  time.Duration // 120s: Bifrost's first boot runs its migrations
	HealthInterval time.Duration // 250ms
	StopTimeout    time.Duration // 15s, then SIGKILL
	BackoffMin     time.Duration // 1s
	BackoffMax     time.Duration // 30s
	StableAfter    time.Duration // 60s healthy resets the backoff
}

type EngineStatus struct {
	Name     string `json:"name"`
	Version  string `json:"version"`
	Up       bool   `json:"up"`
	Restarts int    `json:"restarts"`
}

func New(logger *slog.Logger, versions map[string]EngineVersion, opts Options) *Supervisor // zero opts fields take defaults
func (s *Supervisor) Start(ctx context.Context, engines ...Engine) error // in order; returns once all are healthy
func (s *Supervisor) Stop(ctx context.Context) error                     // reverse order; SIGTERM, then SIGKILL after StopTimeout
func (s *Supervisor) Status() []EngineStatus                            // in start order
func nextBackoff(attempt int, min, max time.Duration) time.Duration      // min * 2^attempt, capped at max
```

Behaviour:
- `Start` verifies each engine (`VerifyBinary` against `versions[e.Name]`) before it launches anything.
- A missing `versions[e.Name]` is `ErrVersionMismatch`.
- Each child's stdout and stderr are logged line by line through `logger.With("engine", name)`.
- When a child exits on its own after `Start`, its status goes to `Up=false` and it restarts after
  `nextBackoff(attempt)`. It goes back to `Up=true` once health passes again.
- A crash-looping engine is retried forever.
- `Start` failing (or `ctx` canceled) kills every child it already started.
- Shortcut: health is probed at start and after each restart only. A hung engine that is still alive is not
  detected. Add a periodic probe when the inference proxy (plan 02) needs it.

**Decision: render on every boot, not only the first.**
- Both files are a pure function of `config.Config` and `Credentials`. remora writes them atomically (temp file plus
  rename) on every start.
- This keeps a changed `REMORA_PORT_ACCOUNTS` working. CLIProxyAPI has no port flag, so its port lives only in
  the file.
- It also follows the spec's "the store wins".
- Static engine settings that later plans need go into these render functions; plan 03's cooldown settings are an
  example. Runtime settings go through the management APIs.
- CLIProxyAPI rewrites `management.secret-key` as a bcrypt hash on load. Re-rendering the plaintext each boot is
  harmless.
- Bifrost hashes the admin password only on first-admin setup (`lib/config.go:1555-1561`).

### Task 11: Fakes binary with a control API

One binary serves every fake upstream on one port, `9090`. Each test names an upstream through a path prefix, so a
base URL like `http://fakes:9090/u/free-a` is one provider, `http://fakes:9090/u/paid-b` is another, and
`http://fakes:9090/u/sx` is a Soniox account. Behaviour is scripted per `(upstream, route)`.
- Plan 01 builds the routing, the control API, recording and scripted replies.
- Every route with no script answers `501 {"error":{"message":"fake: no default for <route>"}}` until a later plan
  adds that route's default behaviour:
  - plan 02: chat stream and non-stream, embeddings;
  - plan 04: Soniox;
  - plan 02 or 05: TypeSafe and decisions.

**Files:**
- Create: `test/fakes/main.go`, `test/fakes/control/control.go`, `test/fakes/control/routes.go`,
  `test/fakes/Dockerfile`
- Modify: `Makefile` (target `fakes-image`, `FAKES_IMAGE ?= remora-fakes:dev`)
- Test: `test/fakes/control/control_test.go`

**Interfaces:**
- Produces the control API contract. Later plans extend `Step` with new fields and register defaults per route; the
  shapes below do not change.

```go
// routes.go: route names, matched under /u/{upstream}
const (
	RouteOpenAIChat           = "openai.chat"           // POST /v1/chat/completions
	RouteOpenAIEmbeddings     = "openai.embeddings"     // POST /v1/embeddings
	RouteOpenAITranscriptions = "openai.transcriptions" // POST /v1/audio/transcriptions
	RouteOpenAIDecisions      = "openai.decisions"      // POST /v1/decisions
	RouteModels               = "models"                // GET  /v1/models
	RouteSonioxFileCreate     = "soniox.files.create"   // POST /v1/files
	RouteSonioxFileDelete     = "soniox.files.delete"   // DELETE /v1/files/{id}
	RouteSonioxTxCreate       = "soniox.transcriptions.create" // POST /v1/transcriptions
	RouteSonioxTxGet          = "soniox.transcriptions.get"    // GET  /v1/transcriptions/{id}
	RouteSonioxTxDelete       = "soniox.transcriptions.delete" // DELETE /v1/transcriptions/{id}
	RouteSonioxTranscript     = "soniox.transcript.get"        // GET  /v1/transcriptions/{id}/transcript
	RouteTypeSafeSystemOne    = "typesafe.systemone"    // POST /v1/systemone
)

type Step struct {
	Status  int               `json:"status"`             // default 200
	Headers map[string]string `json:"headers,omitempty"`  // Content-Type defaults to application/json
	Body    string            `json:"body,omitempty"`     // written verbatim
	DelayMS int               `json:"delay_ms,omitempty"` // before the first byte; honours request cancellation
	SSE     []string          `json:"sse,omitempty"`      // reserved: plan 02 streams these as `data:` events
}
type Script struct {
	Steps  []Step `json:"steps"`
	Repeat bool   `json:"repeat"` // after the last step: true = repeat it, false = fall back to the route default
}
type RecordedRequest struct {
	Route  string      `json:"route"`
	Method string      `json:"method"`
	Path   string      `json:"path"`
	Header http.Header `json:"header"`
	Body   []byte      `json:"body"` // base64 in JSON
	At     time.Time   `json:"at"`
}

type Server struct{ /* mutex-guarded scripts and recordings */ }
func New(defaults map[string]http.HandlerFunc) *Server // route -> default handler; missing = 501
func (s *Server) Handler() http.Handler
```

Control endpoints:
- `PUT /_control/upstreams/{upstream}/routes/{route}` with a `Script` body → 204. An unknown route → 404.
- `GET /_control/upstreams/{upstream}/requests` → 200 `[]RecordedRequest` in arrival order.
- `POST /_control/reset` → 204. It clears the scripts and the recordings.
- `GET /healthz` → 200.

`main.go`:
- `fakes` with no args serves on `FAKES_LISTEN`, default `:9090`.
- `fakes get <url>` prints the status code and exits 0 on 2xx, else 1. It is used for the container HEALTHCHECK and
  for in-network probes in e2e.

`test/fakes/Dockerfile`:
- Build context is the repo root.
- `golang:1.27-trixie` runs `CGO_ENABLED=0 go build -o /out/fakes ./test/fakes`.
- The final stage is `gcr.io/distroless/static-debian13:nonroot`, with `ENTRYPOINT ["/fakes"]`, `EXPOSE 9090` and
  `HEALTHCHECK CMD ["/fakes","get","http://127.0.0.1:9090/healthz"]`.

### Task 13: CI on pull requests

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: Makefile targets; `engines/versions.env`.
- Produces jobs `lint`, `test`, `image` and `e2e`. `image` builds `remora:dev` and `remora-fakes:dev` once and hands
  them to later jobs as the artifact `images` (a `docker save` tarball); plan 07's `quickstart` job loads the same
  artifact. Plan 03 adds the `engine` job (engine-tagged tests against the OAuth engine built from its submodule on
  the runner). Plan 05 adds the OpenAPI drift check. Plan 06 adds UI lint and typecheck.

The workflow:
- Triggers: `on: pull_request` and `push: branches: [main]`.
- `permissions: contents: read`.
- `concurrency`: one run per ref, cancelling any run in progress.
- Actions are pinned by major version: `actions/checkout@v7`, `actions/setup-go@v7` (with
  `go-version-file: go.mod`), `golangci/golangci-lint-action@v9` (`version: v2.14`),
  `docker/setup-buildx-action@v4` and `docker/build-push-action@v7`.

| job | steps |
|---|---|
| `lint` | checkout without submodules; setup-go; golangci-lint |
| `test` | checkout; setup-go; `go test -race ./...` |
| `image` | checkout with `submodules: recursive`; `scripts/check-engine-pins.sh`; `cat engines/versions.env >> "$GITHUB_ENV"`; setup-buildx; build-push-action for the root Dockerfile with `load: true`, `tags: remora:dev`, `platforms: linux/amd64`, the build-args from env (`BIFROST_VERSION`, `CLIPROXYAPI_VERSION`, `REMORA_VERSION`), `cache-from: type=gha,scope=remora` and `cache-to: type=gha,mode=max,scope=remora`; build-push-action for `test/fakes/Dockerfile` (context `.`) with tag `remora-fakes:dev`; `docker save remora:dev remora-fakes:dev -o images.tar`; upload artifact `images` |
| `e2e` | `needs: image`; checkout; download artifact `images`; `docker load -i images.tar`; setup-go; `make e2e` (the harness takes `REMORA_IMAGE` and `FAKES_IMAGE`, defaults `remora:dev` and `remora-fakes:dev`); on failure, upload `docker compose logs` as an artifact |
